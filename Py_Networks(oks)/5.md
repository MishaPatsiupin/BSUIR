# КОНСПЕКТ: DOCSIS, DSL и технологии доступа в интернет

## РАЗДЕЛ 1: DOCSIS (Data Over Cable Service Interface Specification)

### 1. Что такое DOCSIS и для каких целей он применяется?

**DOCSIS** — это стандарт для предоставления широкополосного доступа в Интернет через кабельные телевизионные сети (HFC).

**Назначение:**
- Предоставление услуг передачи данных (Интернет, телефония, видео) по кабельным сетям
- Обеспечение двусторонней связи (upstream/downstream)
- Управление качеством услуг (QoS)
- Безопасность и аутентификация клиентов
- Поддержка различных типов трафика

### 2. Основные версии DOCSIS и их отличия

| Версия | Год | Скорость downstream | Скорость upstream | Особенности |
|--------|-----|-------------------|-------------------|-------------|
| **DOCSIS 1.0/1.1** | 1997/1999 | До 40 Мбит/с | До 10 Мбит/с | Базовая версия, только европейские стандарты |
| **DOCSIS 2.0** | 2002 | До 40 Мбит/с | До 30 Мбит/с | Улучшенная модуляция upstream (QPSK, QAM) |
| **DOCSIS 3.0** | 2006 | До 160+ Мбит/с | До 100+ Мбит/с | Channel bonding, IPv6, улучшенная безопасность |
| **DOCSIS 3.1** | 2013 | До 10 Гбит/с | До 2 Гбит/с | OFDM модуляция, HSD (High-Speed Data) |
| **DOCSIS 4.0** | 2020 | До 10 Гбит/с | До 6 Гбит/с | Симметричные скорости, Full-Duplex (FDX) |

**Ключевые различия:**
- Увеличение пропускной способности
- Расширение поддерживаемых модуляций
- Улучшение механизмов безопасности
- Поддержка новых протоколов (IPv6)

### 3. HFC-сеть в архитектуре DOCSIS

**HFC (Hybrid Fiber-Coaxial)** — гибридная оптоволоконно-коаксиальная сеть

**Структура:**
```
Головная станция (Headend)
         |
    Оптоволокно
         |
    Узел питания (Node)
         |
    Коаксиальный кабель
         |
  Абонентские дома
```

**Компоненты:**
- **Headend** — головная станция, центр управления и источник сигналов
- **Fiber Node** — узел, где оптоволокно преобразуется в коаксиал
- **Coax** — коаксиальный кабель до абонента
- **CM (Cable Modem)** — модем абонента

**Преимущества HFC:**
- Большая пропускная способность благодаря оптоволокну
- Экономичность (использует существующую кабельную инфраструктуру)
- Масштабируемость

### 4. Функции CMTS (Cable Modem Termination System)

**CMTS** — оборудование, устанавливаемое в головной станции провайдера

**Основные функции:**

1. **Управление модемами**
   - Регистрация и аутентификация кабельных модемов
   - Присвоение IP-адресов
   - Контроль состояния модемов

2. **Управление трафиком**
   - Маршрутизация пакетов между CМ и сетью
   - Разделение полосы пропускания между абонентами
   - Управление QoS

3. **Конфигурация модемов**
   - Передача конфигурационных файлов через TFTP
   - Обновление прошивки

4. **Физический уровень**
   - Формирование сигнала downstream (передача в сеть абонента)
   - Приём сигнала upstream от модемов

5. **Безопасность**
   - Аутентификация модемов
   - Шифрование трафика
   - Контроль доступа

### 5. Использование протоколов DHCP, TFTP и TOD в DOCSIS

**DHCP (Dynamic Host Configuration Protocol)**
- **Назначение:** Автоматическое назначение IP-адреса кабельному модему
- **Процесс:** CMTS ← DHCP Server
- **Параметры:** IP, маска, шлюз, DNS, TFTP-сервер

**TFTP (Trivial File Transfer Protocol)**
- **Назначение:** Загрузка конфигурационного файла модема
- **Процесс:**
  1. Модем получает IP-адрес (DHCP)
  2. Получает адрес TFTP-сервера
  3. Загружает файл конфигурации (обычно .cm или .cfg)
- **Содержимое:** Параметры безопасности, параметры каналов, сервисы

**TOD (Time of Day)**
- **Назначение:** Синхронизация времени модема и сети
- **Использование:**
  - Функции безопасности (сертификаты, временные метки)
  - Логирование событий
  - Синхронизация сессий

### 6. Channel Bonding в DOCSIS

**Channel Bonding** — объединение нескольких каналов для увеличения пропускной способности

**Принцип:**
- Несколько физических каналов (от 1 до 32+ для downstream, до 4 для upstream)
- Данные распределяются между каналами параллельно
- Модем и CMTS синхронизируют передачу

**Пример:**
```
CMTS:  [Канал 1] [Канал 2] [Канал 3]
               ↓      ↓      ↓
           Модем (суммирует)
         Итоговая скорость = сумма
```

**Преимущества:**
- Увеличение пропускной способности без расширения спектра
- Использование существующей инфраструктуры
- Гибкость (можно добавлять каналы динамически)

**Требования:**
- Поддержка в модеме и CMTS
- Достаточно свободных каналов в сети

## РАЗДЕЛ 2: DSL технологии

### 7. Что такое DSL и основные типы

**DSL (Digital Subscriber Line)** — технология высокоскоростной передачи данных по медным линиям телефонной сети

**Основные типы DSL:**

1. **ADSL** (Asymmetric DSL)
   - Асимметричная скорость (downstream > upstream)
   - Скорость: 1.5-24 Мбит/с downstream, 0.5-3.5 Мбит/s upstream
   - Использование: Жилые абоненты (веб, видео)

2. **VDSL/VDSL2** (Very-high-bitrate DSL)
   - Высокие скорости: 50-300+ Мбит/s
   - Короткие расстояния до DSLAM (500-1000м)
   - Использование: Современные провайдеры

3. **SDSL** (Symmetric DSL)
   - Одинаковые скорости в обе стороны
   - Использование: Бизнес-клиенты, серверы

4. **HDSL** (High-bitrate DSL)
   - Симметричная передача
   - Старая технология, вытеснена SDSL/VDSL

5. **IDSL** (ISDN-like DSL)
   - Низкие скорости (128 Кбит/s)
   - Работает на любом расстоянии

### 8. Отличие между ADSL и VDSL

| Характеристика | ADSL | VDSL |
|---|---|---|
| **Скорость downstream** | 1.5-24 Мбит/s | 50-300 Мбит/s |
| **Скорость upstream** | 0.5-3.5 Мбит/s | 10-100 Мбит/s |
| **Расстояние** | До 5.5 км | 300-1000м (VDSL2 до 3км) |
| **Технология** | DMT или CAP | DMT (OFDM) |
| **Использование** | Жилые абоненты | Высокоскоростной доступ |
| **Чувствительность к расстоянию** | Умеренная | Высокая |

**Почему VDSL быстрее?**
- Использует более высокие частоты (до 30 МГц вместо 1.1 МГц)
- Более эффективная модуляция
- Меньше помех на коротких расстояниях

### 9. DSLAM и его роль

**DSLAM (DSL Access Multiplexer)** — оборудование в АТС провайдера

**Функции:**
1. **Мультиплексирование**
   - Объединение DSL-линий от абонентов в одно соединение
   - Разделение частот (абонент ↔ DSLAM)

2. **Модуляция/демодуляция**
   - Преобразование цифровых данных в аналоговый сигнал
   - Преобразование аналогового сигнала в цифровой

3. **Фильтрация**
   - Разделение сигнала ISDN/голос и DSL (фильтры Splitter)
   - Подавление помех

4. **Управление**
   - Мониторинг линий
   - Статистика качества
   - Управление QoS

5. **Подключение к магистрали**
   - Соединение с сетью провайдера
   - ATM или Ethernet

### 10. Влияние расстояния на скорость DSL

**Физические причины:**

**1. Затухание сигнала**
```
Сигнал = Исходная мощность / (расстояние²)
```
- Чем дальше абонент, тем слабее сигнал
- Сигнал должен быть выше уровня шума

**2. Диаграмма "зона доступности"**
```
DSLAM
  |
  0 км      ← VDSL2: 50-100 Мбит/s
  |
  0.5 км    ← VDSL2: 20-50 Мбит/s
  |
  1 км      ← VDSL: 10-30 Мбит/s
  |
  2 км      ← ADSL: 5-15 Мбит/s
  |
  4 км      ← ADSL: 1-2 Мбит/s
  |
  5.5 км    ← ADSL: низкая скорость / отсутствие связи
```

**3. Качество медной пары**
- Толщина провода (чем тоньше — больше затухание)
- Возраст кабеля
- Окисление контактов

**4. Помехи**
- Электромагнитные помехи (от соседних линий)
- Помехи от кабельного ТВ
- Электросетевые помехи

### 11. SNR Margin и его значение

**SNR (Signal-to-Noise Ratio) Margin** — запас по соотношению сигнал/шум

**Определение:**
```
SNR Margin = Текущее SNR - Минимально требуемое SNR
```

**Что показывает:**
- **Положительное значение** — линия стабильна
- **Отрицательное значение** — линия может разорваться
- **Близко к нулю** — критическое состояние

**Типичные значения:**
- **> 6 дБ** — хорошее состояние линии
- **3-6 дБ** — среднее состояние
- **0-3 дБ** — плохое состояние, риск разрыва
- **< 0 дБ** — линия неработоспособна

**Факторы влияния:**
- Расстояние (больше расстояние → меньше margin)
- Качество кабеля
- Помехи в окружении
- Затухание на частотах

**Пример:**
```
Абонент близко к DSLAM:    SNR Margin = +12 дБ (стабильно)
Абонент далеко от DSLAM:   SNR Margin = +2 дБ (нестабильно)
Абонент очень далеко:      SNR Margin = -1 дБ (не работает)
```

## РАЗДЕЛ 3: Dial-Up соединение

### 12. Что такое Dial-Up и принцип работы

**Dial-Up** — технология доступа в Интернет через коммутируемую телефонную сеть (PSTN)

**Принцип работы:**

```
Компьютер → Модем → Телефонная сеть → Сервер провайдера → Интернет
```

**Основные этапы:**
1. Компьютер инициирует соединение
2. Модем набирает номер телефона провайдера (серия AT-команд)
3. Модемы устанавливают связь (handshake)
4. Определяются параметры соединения
5. Устанавливается логическое соединение (PPP)
6. Компьютер получает IP-адрес
7. Данные передаются через модулированный сигнал

### 13. Как модем устанавливает связь при Dial-Up

**Процесс установки соединения (Handshake):**

**Этап 1: Инициализация**
- Компьютер отправляет AT-команды модему
- Модем проверяет готовность

**Этап 2: Набор номера**
```
ATD <номер>    ← Набрать номер
```

**Этап 3: Ожидание ответа**
- CONNECT на модеме принимающей стороны
- CONNECT на модеме вызывающей стороны

**Этап 4: Обнаружение (Detection)**
- Модемы обмениваются специальными тонами
- Определяют наличие друг друга
- Согласуют скорость (V.90, V.34 и т.д.)

**Этап 5: Тренировка (Training)**
```
Приемный модем отправляет:  TEST PATTERN (последовательность данных)
Передающий модем:           Адаптирует фильтры (эквализер)
Обратный обмен:             Приемный модем проверяет
```

**Этап 6: Согласование параметров**
- Скорость (1200, 2400, 9600, 14400, 28800, 33600, 56000 бит/s)
- Модуляция (V.34, V.90 и т.д.)
- Коррекция ошибок (V.42)
- Сжатие данных (V.44)

**Этап 7: Рукопожатие PPP**
- Согласование параметров PPP
- Аутентификация (PAP, CHAP)
- Получение IP-адреса (IPCP)

### 14. Максимальные скорости Dial-Up модемов

| Стандарт | Год | Скорость | Технология |
|----------|-----|----------|-----------|
| **V.21** | 1964 | 300 бит/s | Первые модемы |
| **V.22** | 1980 | 1200 бит/s | Duplex |
| **V.32** | 1984 | 9600 бит/s | QAM модуляция |
| **V.32bis** | 1991 | 14400 бит/s | Улучшенная QAM |
| **V.34** | 1994 | 28800-33600 бит/s | TCM модуляция |
| **V.90** | 1998 | **56000 бит/s** | Асимметричная (33600↑/56000↓) |
| **V.92** | 2000 | 56000 бит/s | Улучшенный V.90, функции MOIP |

**Почему V.90 = 56k, а не выше?**
- Закон Найквиста: максимальная скорость в полосе 4 кГц при 8000 Hz sampling
- Правовые ограничения (экспортный контроль для криптографии)
- Оцифровка в телефонной сети ограничивает скорость upstream

### 15. AT-команды модема

**AT-команды (Attention commands)** — текстовые команды для управления модемом

**Синтаксис:**
```
AT[команда][параметры]<CR>
AT → Префикс (модем распознает команду)
<CR> → Символ возврата каретки (Enter)
```

**Основные команды:**

| Команда | Назначение | Пример |
|---------|-----------|--------|
| **D** | Набрать номер | `ATDP 19876543210` (пульсовой) |
| | | `ATDT 19876543210` (тоновой) |
| **H** | Hook control (поднять/опустить трубку) | `ATH0` (отбой), `ATH1` (снять трубку) |
| **E** | Echo (эхо команд) | `ATE0` (отключить), `ATE1` (включить) |
| **V** | Verbose (режим ответов) | `ATV0` (цифровой), `ATV1` (текстовый) |
| **Q** | Quiet (подавление ответов) | `ATQ0` (включить ответы), `ATQ1` (отключить) |
| **M** | Speaker (динамик) | `ATM0` (выключить), `ATM1` (при наборе), `ATM2` (всегда) |
| **L** | Громкость динамика | `ATL0-3` (0=тихо, 3=громко) |
| **S** | Регистры модема | `ATS0=2` (автоответ после 2 звонков) |
| **Z** | Reset (сброс модема) | `ATZ` (на заводские настройки) |
| **&F** | Factory defaults | `AT&F` (фабричные настройки) |
| **&W** | Write (сохранить настройки) | `AT&W` (в NVRAM) |

**Регистры S:**
- **S0** — автоответ (0=нет, 1-255=кол-во звонков)
- **S1** — счётчик входящих звонков
- **S2** — символ Escape (обычно 43 = '+')
- **S3** — символ CR (возврат каретки)
- **S4** — символ LF (переход на новую строку)
- **S6** — ожидание до набора (сек)
- **S7** — ожидание соединения (сек)

**Примеры использования:**
```
AT              ← OK (проверка связи)
ATI             ← OK (информация о модеме)
AT&V            ← Показать текущие настройки
ATD 19876543210 ← Набрать номер
+++ (без Enter) ← Перейти в командный режим при соединении
ATH0            ← Разорвать соединение
```

### 16. Ключевые отличия Dial-Up от DSL

| Параметр | Dial-Up | DSL |
|----------|---------|-----|
| **Среда передачи** | Телефонная линия (PSTN) | Телефонная линия (PSTN) |
| **Скорость** | До 56 Кбит/s | 1-300+ Мбит/s |
| **Использование телефона** | Соединение занимает линию | Одновременно с телефоном (через Splitter) |
| **Установка** | Каждый раз набор номера | Постоянное соединение |
| **Способ модуляции** | Базовая модуляция (QAM) | DMT (OFDM) модуляция |
| **Расстояние** | Без ограничений | До 5.5 км (ADSL) или 1 км (VDSL) |
| **Зависимость от расстояния** | Слабая | Очень сильная |
| **Надежность** | Средняя | Высокая |
| **Задержка (Latency)** | 100-500 мс | 10-50 мс |
| **Стоимость** | Невысокая | Выше, чем Dial-Up |
| **Технология** | Старая (1990-е) | Современная |

## РАЗДЕЛ 4: Протоколы аутентификации

### 17. PPP (Point-to-Point Protocol) и его назначение

**PPP** — протокол канального уровня для прямого соединения между двумя узлами

**Назначение:**
- Установление соединения между компьютером и сервером доступа
- Передача протоколов сетевого уровня (IP, IPX, AppleTalk)
- Аутентификация пользователя
- Назначение IP-адреса
- Сжатие и шифрование данных

**Структура PPP-кадра:**
```
┌─────┬─────┬──────┬─────────┬──────┐
│Flag │Addr │Ctrl │ Protocol│Data  │
│ 1B  │ 1B  │ 1B  │  2B     │ var  │
└─────┴─────┴──────┴─────────┴──────┘
```

**Компоненты PPP:**

1. **LCP (Link Control Protocol)**
   - Установление и завершение соединения
   - Согласование параметров
   - Обнаружение ошибок

2. **Authentication Protocols**
   - PAP (Password Authentication Protocol)
   - CHAP (Challenge Handshake Authentication Protocol)

3. **NCP (Network Control Protocol)**
   - IPCP (IP Control Protocol) — для IPv4
   - IPV6CP — для IPv6

**Процесс установления PPP:**
```
1. LCP Open Phase      ← Согласование параметров
2. Authentication      ← PAP или CHAP
3. NCP Open Phase      ← Получение IP-адреса (IPCP)
4. Network Layer Phase ← Передача данных
5. LCP Close Phase     ← Завершение соединения
```

### 18. PAP (Password Authentication Protocol)

**PAP** — простейший протокол аутентификации

**Принцип работы (2-way Handshake):**

```
Клиент                         Сервер
   |                              |
   | ---  PAP Request  ----→      |
   |   (username, password)       |
   |                              |
   |      Проверка базы данных    |
   |                              |
   |      ←---- PAP Reply ------   |
   |      (Accept/Reject)         |
```

**Процесс:**
1. Клиент отправляет свои учетные данные (username:password)
2. Сервер проверяет в базе данных
3. Сервер отправляет Accept (успешно) или Reject (ошибка)
4. Учетные данные могут быть отправлены многократно

**Протокольные пакеты:**
- **PAP Request** (код 1)
- **PAP Ack** (код 2) — успешная аутентификация
- **PAP Nak** (код 3) — ошибка аутентификации

**Параметры:**
- Длина пакета: 1500 байт
- Идентификатор транзакции для отслеживания
- Переменная длина имени пользователя и пароля

### 19. CHAP (Challenge Handshake Authentication Protocol)

**CHAP** — протокол аутентификации на основе challenge-response

**Отличие от PAP:**
- Пароль **не передается открытым текстом**
- Использует криптографическое хеширование (обычно MD5)
- Более безопасен

**Принцип работы (3-way Handshake):**

```
Клиент                         Сервер
   |                              |
   |      ←---- CHAP Challenge --  |
   |      (Challenge value, ID)    |
   |                              |
   | ---- CHAP Response ---→      |
   | (MD5(ID|Password|Challenge)) |
   |                              |
   |      ←---- CHAP Success ----  |
   |      (или Failure)            |
```

### 20. Механизм Challenge-Response в CHAP

**Детальный процесс:**

**Шаг 1: Сервер отправляет Challenge**
```
Challenge Packet:
├─ Code: 1 (Challenge)
├─ ID: Random identifier
├─ Challenge Value: случайные 16-24 байта
└─ Name: имя сервера
```

**Шаг 2: Клиент вычисляет Response**
```
Response = MD5(ID | Password | Challenge)

Пример:
ID = 0x42
Password = "secret123"
Challenge = 0x1A2B3C4D5E6F7A8B9C0D1E2F3A4B5C6D

MD5(0x42 + "secret123" + 0x1A2B3C...) = 0xABC123...
```

**Шаг 3: Клиент отправляет Response**
```
Response Packet:
├─ Code: 2 (Response)
├─ ID: Same as Challenge
├─ Response Value: результат MD5
└─ Name: имя пользователя
```

**Шаг 4: Сервер проверяет**
```
1. Сервер вычисляет MD5(ID | Password_in_DB | Challenge)
2. Сравнивает с полученным Response
3. Если совпадает → Success
   Если не совпадает → Failure
```

**Преимущества Challenge-Response:**
- Пароль не передается в открытом виде
- Каждое соединение использует новый Challenge
- Защита от Replay-атак (старый Challenge не подойдет)
- Защита от Man-in-the-Middle на уровне аутентификации

**Дополнительно в CHAP:**
- **Periodic Re-authentication** — периодическая переаутентификация
- **Mutual Authentication** — обе стороны могут требовать аутентификации друг друга
- **Multiple Challenge-Response** — несколько попыток

### 21. Использование PAP несмотря на недостатки

**Когда может использоваться PAP:**

**1. Технические ограничения**
- Старое оборудование, не поддерживающее CHAP
- Устаревшие компоненты сети, совместимые только с PAP
- Оборудование из 1980-90х годов

**2. Простота реализации**
- PAP проще реализовать для встроенных систем
- Требует меньше вычислительных ресурсов
- Быстрее проходит аутентификация

**3. Сценарии низкого риска**
```
Примеры:
┌─ Корпоративная закрытая сеть (Intranet)
│  └─ Только авторизованные пользователи имеют доступ
│
├─ Внутренняя VPN компании
│  └─ Трафик по защищённому каналу (IPSec, TLS)
│
└─ Лабораторные и тестовые окружения
   └─ Не содержат чувствительные данные
```

**4. Дополнительная защита**
- PAP может использоваться, если данные дополнительно шифруются на прикладном уровне
- Пример: PAP поверх SSL/TLS
- Канальное шифрование (Link Encryption)

**5. Специфичные требования приложений**
- Некоторые приложения явно требуют PAP для совместимости
- Legacy системы, критичные для бизнеса

**6. Комбинированные подходы**
- PAP для быстрой проверки (быстрая аутентификация)
- CHAP для дополнительной безопасности
- Двухфакторная аутентификация с PAP

**Рекомендации безопасности:**
- ❌ **ИЗБЕГАТЬ** использования PAP в открытых сетях
- ❌ **ИЗБЕГАТЬ** PAP для передачи чувствительных данных
- ✅ **ИСПОЛЬЗОВАТЬ** CHAP для современных систем
- ✅ **ИСПОЛЬЗОВАТЬ** MS-CHAP v2, RADIUS, EAP для высокого уровня безопасности
